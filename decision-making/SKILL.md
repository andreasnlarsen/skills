# Decision Making

Use this skill to apply this company decision-making process. The durable model scope is **all decisions that can be made by any person in a company**, not a requester-scoped or agent-scoped subset.

For eligible substantial decisions, template work, strategically important choices, or eligible requests that mention MECE/categorical decision models, read `references/playbook.md` before doing the work.

## Hard Boundaries

- Use `$mece-thinking` whenever parent set, abstraction level, or bucket exclusivity matters. Follow its strict default and narrow `~MECE` utility exception.

## Source Anchors

No template or source document ships with this skill. When the user asks to fill, update, or recreate a decision template, ask for their own decision template (for example a Google Sheets or Excel file, with its link or path) and any source framework material they want followed, and use those as retrieval sources. Without a template, build the record from the structure in `references/playbook.md`.

## Choose the operation

Use the playbook's operating modes: facilitated record by default when the user is the decision-maker, autonomous recommendation when delegated, audit of an existing record, or execution-reopen triage. Split compound requests into the relevant phases. Facilitation, artifact, rigor, and permitted delegation are separate settings, not company-decision categories. Prefer Google Sheets when the user wants a durable visual framework; use the requested artifact otherwise.

## First Classification

Classify the immediate decision object with the playbook's Model 1: company priority, outcome-group definition, path-to-outcome, or execution. Classify one atomic decision about one layer at a time. Link compound decisions instead of choosing a primary label.

## Apply the process

Follow the relevant branch and models in `references/playbook.md`. For path decisions, define the outcome group before inversion and options; keep mandatory gates separate from graded preferences, reject unlivable downsides, evaluate comparable consequences, mitigate, and resolve.

Make the requested decision record usable: record the outcome definitions, evidence and assumptions, options and consequences where applicable, risks, resolution, first action, owner, and review triggers. An audit leads with concrete findings; an autonomous recommendation exposes uncertainty and what could reverse it. A short answer can be concise without skipping the applicable decision gates. Use the playbook's mode and artifact guidance for the depth needed.
